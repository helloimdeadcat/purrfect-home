## 1. Распаковать и установить зависимости

Нужен **Node.js 22.12 или новее** (проверить: `node -v`). На Node 20 тесты (vitest 5) не запустятся.

```bash
tar -xzf purrfect-home-2026-10-27.tar.gz
cd family-finance
npm install
npm test          # все тесты должны пройти
```

Обычный `npm install`, **без** `--legacy-peer-deps` и `--force`. Раньше без этих флагов
установка падала с ошибкой `ERESOLVE` (на Vercel тоже) — это исправлено, см. раздел 8.

## 2. Применить миграции базы (обязательно, один раз)

На удалённом Supabase сейчас только миграции 1–8. Новые функции (настройки,
уведомления, дела, привычки, питание, русские тексты базы, лимит ИИ, push-уведомления,
автоочистка) работают только после миграций 9–20 — они все собраны в один файл.

1. Открыть https://supabase.com/dashboard → свой проект → **SQL Editor** → **New query**.
2. Открыть файл `supabase/pending/apply-pending-migrations.sql`, скопировать **весь** текст, вставить, нажать **Run**.
3. Внизу появится таблица-чек-лист: **во всех строках `ok = true`**.
   - Если где-то `false` или ошибка — ничего не трогать, сохранить текст ошибки и прислать мне.
   - Повторный запуск безопасен (все миграции идемпотентны).
4. Проверить с компьютера:
   ```bash
   npm run check:remote
   ```
   Все пункты должны быть отмечены как OK.

## 3. Морти — ИИ-помощник (Gemini, бесплатно)

**Ключ уже добавлен** в `.env.local` (строка `AI_API_KEY=…`, взят из присланного `env.local.download`).
Сам файл `Desktop\fam\env.local.download` лучше удалить — в нём лежат все ключи открытым текстом.

### Проверить, что Gemini работает

```bash
npm run check:ai
```

Проверка шлёт в Google только **выдуманные** тестовые вопросы (база не используется) и проверяет:

1. ключ и модель принимаются, Google принимает описания инструментов Морти;
2. Морти отвечает и представляется по имени;
3. на просьбу «Добавь мне дело» Морти **предлагает карточку**, а не меняет данные сам.

Результат 27.10.2026: ✅ ключ рабочий, все 3 проверки прошли. Ответ Морти:
«Привет! Меня зовут Морти, я твой домашний помощник в Purrfect Home 🐾».
На просьбу добавить дело он показал карточку «Добавить «купить молоко» · … · 2026-10-28».

В тот день Google был перегружен: основная модель отвечала 503, запасная — за 12–22 секунды,
и один прогон проверки упал по таймауту («Морти слишком долго думал»). Если `check:ai` падает
именно так — это нагрузка у Google, а не поломка: повторить позже.

### Модели и запасная модель

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `AI_MODEL` | `gemini-flash-latest` | основная модель (умнее) |
| `AI_FALLBACK_MODEL` | `gemini-flash-lite-latest` | если основная перегружена, долго молчит (25 с) или кончилась её бесплатная квота — тот же вопрос автоматически уходит сюда; `off` — отключить |

Зачем запасная: во время проверки `gemini-flash-latest` у Google была перегружена
(ошибка 503 «high demand» и ответы дольше минуты), а `gemini-flash-lite-latest` отвечала за секунды.
Теперь пользователь в такой момент просто получает ответ от lite-модели.

⚠️ Старые модели `gemini-2.5-flash` и `gemini-2.5-flash-lite` **недоступны для новых ключей** (Google отвечает 404) —
не прописывай их в `AI_MODEL`.

### Защита от долгих ответов и лимитов

- Ход Морти ограничен **75 секундами**: если Google тормозит, Морти отвечает тем, что успел
  («Я не успел всё проверить…»), а не висит.
- Если основная модель не ответила, следующие 5 минут запросы сразу идут в запасную — без ожидания.
- Лимит на человека: **20 запросов к ИИ за 10 минут и 100 в сутки** (вопросы Морти и распознавание чеков вместе).
  Счётчик хранится в базе, поэтому работает и на Vercel (раньше был в памяти сервера и на Vercel фактически не работал).

### Важно про данные

Вопросы и данные, которые Морти смотрит (еда, дела, привычки, балансы), уходят в Google;
на бесплатном тарифе Google может использовать их для улучшения своих моделей.
Морти ничего не меняет сам: он показывает карточку, изменение происходит только по кнопке **«Применить»**.

## 7. Чеки: распознавание и хранение

### Распознать чек (новое)

Операции → форма добавления расхода → **«📷 Распознать чек»** (на телефоне сразу открывается камера).

- Фото уменьшается прямо в браузере (до 1600 px) и отправляется **только в Gemini** — в базе и хранилище оно **не сохраняется**.
- Морти заполняет сумму, дату, магазин, категорию (из ваших категорий) и до 5 позиций в описание.
  То, что уже введено вручную, он не перезаписывает. **Перед сохранением проверь сумму и дату.**
- PDF не распознаётся — только фото.
- Считается в общий лимит ИИ (20 за 10 минут / 100 в день).
- Проверено на пустой тестовой картинке; на настоящем чеке — проверь сама (чек-лист, раздел 6).
  Для автопроверки можно положить фото чека в `services/__fixtures__/receipt.jpg` (в git не попадёт) и запустить `npm run check:ai`.

### Прикрепить фото чека (как раньше)

Если фото нужно сохранить — прикрепи его к операции, как раньше:

- файл (JPEG, PNG, WebP, HEIC или PDF, до 8 МБ) загружается в **приватное** хранилище
  Supabase Storage (bucket `receipts`), путь `семья/операция/файл`;
- большие фото теперь **сжимаются в браузере** перед загрузкой (до 2000 px, JPEG) — экономит место;
- на семью — не больше **800 МБ** чеков (бесплатный Supabase даёт 1 ГБ); при превышении приложение попросит удалить старые;
- видеть чек могут только участники семьи, открывается он по временной ссылке;
- при удалении чек стирается и из хранилища; чеки удалённых операций автоматически чистятся через 30 дней.

## 7в. Чтобы не упираться в лимиты бесплатных сервисов

| Сервис | Лимит (бесплатно) | Что сделано |
|---|---|---|
| Supabase, база (500 МБ) | — | Ежедневная автоочистка: прочитанные уведомления старше 60 дней, любые — старше 180; история действий старше 365 дней; старые отозванные/просроченные приглашения (30 дней); удалённые операции без чеков старше 90 дней. **Живые деньги, счета, цели, бюджеты не трогаются никогда.** Отметки привычек и дел сохраняются (нужны для серий). |
| Supabase, Storage (1 ГБ) | — | Сжатие фото, потолок 800 МБ на семью, автоудаление чеков удалённых операций и «потерянных» файлов |
| Supabase, трафик (5 ГБ/мес) | — | Страницы больше не грузят все операции ради выпадающего списка счетов; сводка и рассылка выбирают только нужные поля |
| Supabase, «засыпание» через 7 дней без активности | — | Ежедневная задача сама обращается к базе — проект не уснёт |
| Gemini (бесплатные запросы в день) | — | Лимит 20/10 мин и 100/день на человека, запасная модель, фото уменьшаются перед отправкой |
| Vercel Hobby (cron раз в день, время функций) | — | Одна ежедневная задача; у Морти и распознавания жёсткий потолок времени |

**Настройки → «Использование»** (видно владельцу/админу): сколько чеков и МБ из 800, сколько уведомлений и записей истории.

Ежедневная задача — `/api/cron/daily` (расписание в `vercel.json`, 05:00 UTC): сначала очистка, потом утренние push.
Она защищена секретом `CRON_SECRET` (Vercel передаёт его сам, если переменная задана).

## 8. Деплой на Vercel

### Что было сломано и как исправлено (27.10.2026)

- **Ошибка:** `npm install` на Vercel падал с `ERESOLVE`: `vitest@5.0.5` требует
  `@types/node@^22.0.0 || >=24.0.0`, а в `package.json` стояло `@types/node: ^20`.
- **Исправление:** `@types/node` обновлён до `^22` (установилась 22.20.5) — подходит и vitest 5.0.5,
  и vite 8.3.4 (`^20.19 || >=22.12`), и Next 16.3.7 (Node `>=20.9`). Остальные зависимости не трогали,
  обходные флаги `--force` / `--legacy-peer-deps` не используются. `package-lock.json` синхронизирован обычным `npm install`.
- **Предупреждение `Unknown env config "cache-dir"`:** в проекте нет `.npmrc`, и ни в пользовательских,
  ни в глобальных настройках npm такого параметра нет — предупреждение идёт из окружения сборки Vercel,
  а не из проекта. На установку не влияет, исправлять в проекте нечего.
- Проверено: `npm ci` с нуля, `npm ls`, тесты, ESLint, `npm run build`, `tsc` — всё без ошибок.
- **Безопасность:** Next.js обновлён 16.3.7 → **16.4.3** — в 16.3.7 были критические уязвимости
  (в т.ч. удалённое выполнение кода через оптимизацию картинок и `use cache`). Остальные уязвимости
  закрыты обычным `npm audit fix` (без `--force`): **`npm audit` — 0 уязвимостей**.
- Добавлен пакет `web-push` (push-уведомления).

### Настройки Vercel (один раз)

1. **Settings → Build and Deployment → Node.js Version:** `22.x` или `24.x` (не 20.x).
2. **Settings → Environment Variables** — те же переменные, что в `.env.local`:
   - `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`;
   - `AI_API_KEY` — **без него Морти на сайте не заработает** (локальный `.env.local` на Vercel не попадает);
   - `APP_URL=https://твой-адрес.vercel.app` — чтобы ссылки-приглашения были правильными;
   - `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` — для push (значения из `.env.local`;
     `VAPID_SUBJECT` замени на настоящий адрес: `mailto:твоя@почта`);
   - `CRON_SECRET` — значение из `.env.local`; без него ежедневная очистка и утренние push не запустятся;
   - по желанию `AI_MODEL`, `AI_FALLBACK_MODEL`.

   `SUPABASE_SERVICE_ROLE_KEY`, `AI_API_KEY`, `VAPID_PRIVATE_KEY`, `CRON_SECRET` — только серверные,
   **никогда** не с префиксом `NEXT_PUBLIC_`.
3. После первого деплоя проверить **Settings → Cron Jobs**: там должна появиться задача `/api/cron/daily`
   (можно нажать «Run» и посмотреть ответ в логах).

## 12. Если что-то пошло не так

| Симптом | Что сделать |
|---|---|
| `npm install` / Vercel: `ERESOLVE` | Убедиться, что в `package.json` `@types/node` = `^22` и закоммичен свежий `package-lock.json`. Флаги `--force` / `--legacy-peer-deps` **не** использовать |
| Vercel: ошибка про версию Node / `engine` | Node.js Version в настройках Vercel → `22.x` или `24.x` |
| Vercel: предупреждение `Unknown env config "cache-dir"` | Безвредно, идёт из окружения Vercel |
| Страницы Привычки/Питание/Дела пустые или с ошибкой про таблицу | Не применены миграции — раздел 2 |
| `check:remote` показывает FAIL | Прислать мне вывод целиком |
| Морти: «ещё не настроен» | Нет `AI_API_KEY` в `.env.local` (локально) или в Environment Variables (Vercel); после добавления перезапустить `npm run dev` / сделать Redeploy |
| Морти: ошибка 429 / «слишком много вопросов» | Лимит: 20 вопросов за 10 минут или лимит бесплатного Gemini — подождать |
| Морти: ошибка модели (404) | В `AI_MODEL` прописана устаревшая модель — удалить строку `AI_MODEL` (будет `gemini-flash-latest`) |
| Морти долго думает / 503 | Google перегружен; запасная модель подхватит сама. Проверить: `npm run check:ai` |
| На телефоне старая версия страницы | Закрыть и открыть приложение / обновить страницу (кэш PWA) |
| Push: «не настроено на сервере» | Нет `VAPID_*` в `.env.local` / на Vercel → добавить и Redeploy |
| Push не приходят на iPhone | Приложение должно быть добавлено на главный экран (iOS 16.4+) и открыто с него; включить заново в Настройках |
| Push перестали приходить после смены VAPID-ключей | На каждом телефоне выключить и снова включить уведомления в Настройках |
| Нет утренней сводки | Vercel → Settings → Cron Jobs: есть ли `/api/cron/daily`, задан ли `CRON_SECRET`; в логах ответ задачи |
| Чек не распознаётся | Только фото (не PDF); если «слишком много» — лимит 20 за 10 минут; при 502 — Google перегружен, повторить |
| «Место для чеков закончилось» | Удалить старые прикреплённые чеки (Настройки → «Использование» покажет, сколько занято) |
